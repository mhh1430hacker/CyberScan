## What each tool does

**081 Source Code Security Scanner** - Static analysis for injection sinks, disabled TLS verification, weak crypto, insecure randomness, debug mode, insecure temp files and permissions in Python (AST), JS/TS, PHP, Java, Go, C/C++, C# and Ruby.

Data handling: Source code is analysed in memory and never executed or stored. External: None. Timeout: 60 s. Source: CyberScan original implementation; rule categories follow CWE (78, 94, 95, 295, 327, 330, 377, 489, 732).

**082 Dependency Vulnerability Checker** - Finds dependency versions affected by OSV advisories: offline against advisories you supply, or (opt-in) via the public OSV.dev API. Supports 12 manifest/lockfile formats across PyPI, npm, Go, RubyGems, Packagist, crates.io, Maven.

Data handling: Manifests are parsed in memory. External: Only with online=true: package names, ecosystems and versions are sent to https://api.osv.dev. Timeout: 60 s. Source: CyberScan original implementation; OSV schema; optional OSV.dev API (Google, data CC-BY 4.0); packaging (Apache-2.0/BSD).

**083 Secrets Scanner** - Scans a set of files or a local directory for committed secrets, de-duplicates them by fingerprint, downgrades test/docs matches and flags secret-bearing files (.env, keys, keystores). Values are never shown.

Data handling: Files are read in memory; secret values are fingerprinted and masked, never returned. External: None. Timeout: 90 s. Source: CyberScan original implementation; reuses detection.secrets.scan_secrets (frozen engine).

**084 License Compliance Checker** - Classifies dependency licenses (SPDX expressions, free-text names, LICENSE file texts) and flags conflicts with the chosen distribution model (proprietary, SaaS, internal, open source) plus allow/deny lists. Not legal advice.

Data handling: Package names and license strings are analysed in memory. External: None. Timeout: 30 s. Source: CyberScan original implementation; license identifiers from the SPDX License List.

**085 SBOM Generator** - Generates a reproducible CycloneDX 1.5 JSON SBOM (components, purls, scopes, licenses, hashes) from manifests and lockfiles, and reports unresolved versions and missing hashes.

Data handling: Manifests are parsed in memory; the SBOM is returned, not stored. External: None. Timeout: 60 s. Source: CyberScan original implementation; CycloneDX 1.5 specification (OWASP).

**086 Lockfile Integrity Checker** - Audits lockfiles and requirements for unpinned versions, missing/weak integrity hashes, HTTP or git sources, extra indexes (dependency confusion), trusted hosts and manifest/lockfile drift.

Data handling: Lockfiles are parsed in memory. External: None. Timeout: 30 s. Source: CyberScan original implementation.

**087 Unsafe Deserialization Detector** - Finds unsafe deserialization in Python, Java, .NET, PHP, Ruby and Node code, and inspects serialized blobs (pickle opcodes, Java/.NET/PHP formats) without loading them.

Data handling: Code and blobs are analysed in memory; blobs are never deserialized. External: None. Timeout: 60 s. Source: CyberScan original implementation (CWE-502).

**088 SQL Injection Pattern Detector** - Detects SQL built by concatenation, f-strings, % or .format instead of bound parameters (Python AST; JS/TS, PHP, Java, C#, Go, Ruby patterns), with higher severity when request input is read nearby.

Data handling: Source code is analysed in memory and never executed. External: None. Timeout: 60 s. Source: CyberScan original implementation (CWE-89).

**089 XSS Pattern Detector** - Detects cross-site-scripting patterns: DOM sinks, framework escape hatches, disabled template auto-escaping, javascript: URLs, PHP echo of request data and Flask render_template_string, with source-aware severity.

Data handling: Source code is analysed in memory and never executed. External: None. Timeout: 60 s. Source: CyberScan original implementation (CWE-79).

**090 Secure Configuration Analyzer** - Checks Django, nginx, Apache, php.ini, .env and Spring Boot configuration for debug mode, wildcard hosts/CORS, insecure cookies, directory listing, version disclosure, legacy TLS, exposed actuators and hard-coded secrets.

Data handling: Configuration is analysed in memory; secret values are masked. External: None. Timeout: 30 s. Source: CyberScan original implementation; checks follow OWASP ASVS V14 and vendor hardening guides.
