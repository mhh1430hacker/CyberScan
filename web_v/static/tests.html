The method, the real numbers from the latest run, and an honest list of what has not been measured.الطريقة، والأرقام الحقيقية من آخر تشغيل، وقائمة صادقة بما لم يُقَس بعد.

How we test

We run the same engine the website uses (ScanService, with its default settings and online lookups switched off so runs are repeatable) over two sets of files, with the script tools/bench_engine.py. Everything below is produced by that script; nothing is typed by hand.

  1. Clean files (false alarms). A fixed random sample of files that are known not to be malware: this website's own code, images and fonts, and the files of well-known open-source packages installed in the project's Python environment, including real Windows programs (.pyd/.dll from numpy, PySide6, Pillow and others). Windows system files are not used. Any “Suspicious” verdict on these files is a false alarm; a “take a look” note is a milder signal that we also count.
  2. Synthetic samples. Small, inert files built byte by byte from the project's test fixtures (tests/repair_fixtures.py and the strings the unit tests use). They have the shape of common attacks (a PDF that runs a script when opened, an encoded PowerShell command, a document that is really a program, data hidden before an archive) but contain nothing that can run. These are checked in memory, because Microsoft Defender on the test machine quarantines byte-built test programs as soon as they are written to disk.

What this does not measure

  • Detection of real malware. No live malware, no downloaded samples and not even the EICAR test file were used, so this page gives no malware detection rate. Seven synthetic samples cannot stand in for one.
  • Files larger than 4 MB (the website's limit), and online threat-intelligence lookups.
  • Independent labs have not tested CyberScan yet. If you run a test lab and want to, please get in touch.

كيف نختبر

نشغّل المحرك نفسه الذي يستخدمه الموقع (ScanService بإعداداته الافتراضية مع إيقاف البحث عبر الإنترنت ليمكن تكرار النتائج) على مجموعتين من الملفات، بواسطة البرنامج tools/bench_engine.py. كل ما يلي ينتجه هذا البرنامج، ولا شيء مكتوب يدويًا.

  1. ملفات نظيفة (الإنذارات الكاذبة). عينة عشوائية ثابتة من ملفات معروف أنها ليست برمجيات خبيثة: شيفرة هذا الموقع وصوره وخطوطه، وملفات حزم مفتوحة المصدر معروفة مثبتة في بيئة Python للمشروع، ومنها برامج Windows حقيقية (‎.pyd/.dll من numpy وPySide6 وPillow وغيرها). لم تُستخدم ملفات نظام Windows. أي حكم «مشبوه» على هذه الملفات إنذار كاذب، وملاحظة «يستحق نظرة» إشارة أخف نحسبها أيضًا.
  2. عينات اصطناعية. ملفات صغيرة خاملة مبنية بايتًا بايتًا من أدوات اختبار المشروع (tests/repair_fixtures.py والنصوص التي تستخدمها اختبارات الوحدات). لها شكل هجمات شائعة (ملف PDF يشغّل سكربتًا عند فتحه، وأمر PowerShell مُرمّز، ومستند هو في الحقيقة برنامج، وبيانات مخفية قبل أرشيف) لكنها لا تحتوي على شيء يمكن تشغيله. تُفحص في الذاكرة، لأن Microsoft Defender على جهاز الاختبار يحجر برامج الاختبار المبنية يدويًا فور كتابتها على القرص.

ما الذي لا يقيسه هذا

  • كشف البرمجيات الخبيثة الحقيقية. لم تُستخدم برمجيات خبيثة حيّة ولا عينات منزّلة ولا حتى ملف اختبار EICAR، لذا لا تقدم هذه الصفحة أي نسبة لكشف البرمجيات الخبيثة. سبع عينات اصطناعية لا تغني عن ذلك.
  • الملفات الأكبر من 4 ميغابايت (حد الموقع)، والبحث في معلومات التهديدات عبر الإنترنت.
  • لم تختبر مختبرات مستقلة CyberScan بعد. إذا كنت تدير مختبر اختبار وتريد ذلك، تواصل معنا.
