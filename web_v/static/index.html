        Stage 01 · Implemented

        Static structural analysis

        In plain words

        A Windows program is like a parcel with a label and a packing list. CyberScan reads the label (what the program says it is), the packing list (the system functions it asks for) and the seal (its digital signature) without opening the parcel. A 'photo viewer' that asks for the tools to watch the keyboard doesn't add up.

        A Windows program (PE file) is a documented data structure. CyberScan parses it with pefile: the header, each section's flags and size, the import table, the version resource, and the Authenticode signature. Nothing is loaded or executed.

        Input
        File bytes, SHA-256, magic bytes
        Output
        Sections (writable/executable, entropy), imports, claimed identity, signature state
        Contributes
        Suspicious imports, writable + executable sections, and a name or version resource that contradicts the program's capabilities

        Source: core/pe_decompiler.py, core/authenticode.py, core/dissonance.py

        Stage 02 · Implemented

        Entropy topography

        In plain words

        Entropy measures how predictable the bytes are. A page of text repeats letters and words, empty space is all the same, and encrypted data looks like pure noise. CyberScan draws this level along the whole file; a sudden jump from ordinary content to noise is often where something packed or hidden begins.

        The project calls this "thermodynamic entropy topography", but the quantity is Shannon's information entropy, not physical entropy. For each window of n bytes with byte counts cx:

        H = −Σ px log2 px = log2 n − 1⁄n Σ cx log2 cx

        The window slides through the file, and the engine updates the counts incrementally (only bytes entering and leaving the window change the sum). The result is a curve of bits per byte: 0 for constant filler, around 4–5 for text and code, close to 8 for compressed or encrypted data.

        A discontinuity is recorded where adjacent windows differ by |ΔH| ≥ 1.5 bits, or where the curve jumps from below 3.5 to above 7.2. Such a boundary often marks where an encoded payload begins.

        Input
        Raw bytes; window 128 B, step 32 B (4096 B / 1024 B in the file scan)
        Output
        Trajectory, gradients, mean, peak, variance, anomalies with offsets
        Contributes
        "High entropy" (+18) and "Entropy discontinuity" (+12) findings, ATT&CK T1027

        Source: core/entropy.py, core/nextgen_engine.py

        Stage 03 · Implemented · programs only

        Positional surprise

        In plain words

        Noise-like data is normal in some places and not in others: a compressed photo inside a program's resources is fine, the same noise inside its code is not. CyberScan learned what honest programs keep in each part and points out pieces that are out of place.

        Entropy alone cannot tell a compressed picture in the resource section (normal) from encrypted bytes in the code section (not normal): both are close to 8 bits per byte. What differs is where they are. CyberScan learned, from benign programs only, the byte distribution Q of each part of a program (header, code, data, resources, overlay). For every 4 KiB window it measures the Kullback–Leibler divergence from that part's distribution:

        DKL(P ‖ Q) = Σ px log2 (px ⁄ qx)

        That is the extra bits per byte needed to compress the window with a code built for honest content of its kind. A window above the benign 99.9th percentile for its part (and at least 0.75 bits) is flagged as foreign.

        Input
        PE sections by role; a pinned profile (256 frequencies + quantiles per role)
        Output
        Per-part surprise, foreign regions with offsets

        Source: core/surprise_map.py · profile fitted on 1,500 benign Windows programs (per source comments)

        Stage 04 · Implemented · x86 / x86-64

        Control-flow graph reconstruction

        In plain words

        Without running the program, CyberScan translates its machine code into instructions and maps how it can jump between them, like drawing a city's road map without driving. One road shape is telling: a tight loop that rewrites memory piece by piece, which is how hidden code decrypts itself.

        The code section is decoded with the Capstone disassembler in a linear sweep. An instruction starts a new basic block if it is the first, the target of a branch, or follows a branch, call or return. Edges connect a block to its branch target and, unless it ends in an unconditional jump or return, to the block that follows.

        M = E − N + 2P

        Cyclomatic complexity counts independent paths (E edges, N blocks, P connected components). An edge to an earlier block is a back edge, meaning a loop. The warning pattern is deliberately strict: a short loop (≤ 48 instructions) that XORs into memory while stepping a counter, which is the shape of an in-place decryption stub. In a program, it also requires somewhere to decrypt into (a writable + executable or high-entropy section).

        Input
        Entry-point code section, up to 256 KiB; architecture from the PE header
        Output
        Blocks, edges, M, density, back edges, opcode mix, patterns
        Contributes
        "Static decoding indicator" (+15), ATT&CK T1027; skipped for .NET and non-x86 code

        Source: core/nextgen_engine.py · extract_cfg_topology

        Stage 05 · Implemented · classifier inactive without an approved model

        The 4096-dimensional representation

        In plain words

        All the measurements are packed into one list of 4,096 numbers, a fingerprint of the file's shape. Files built alike get similar fingerprints, which is what a learning model needs. It is a fixed recipe, not a 'brain', and the model that would read it stays off until someone installs one they have reviewed.

        Every measurement above is folded into one fixed-length vector of 4096 numbers: four channels of 1024. Variable-size features (byte n-grams, opcodes, graph edges, imports) are placed by feature hashing: a BLAKE2b digest of the feature's name picks its coordinate, so any file maps to the same space without a vocabulary.

        1. 0–1023 byte histogram (256) + hashed 2/3/4-byte n-grams and opcode frequencies
        2. 1024–2047 entropy trajectory and its gradients, resampled to 512 + 512
        3. 2048–3071 graph metrics, block out-degrees, hashed edges and patterns
        4. 3072–4095 PE header values, section sizes, hashed import names

        Each channel is scaled to unit length, then the whole vector, so no single kind of evidence dominates. This is a lossy, deterministic projection. It is not a learned neural embedding.

        How it is used: a random-forest classifier (clean / suspicious / malware) with conformal abstention reads these coordinates, but only when an operator installs a model whose SHA-256 they approve. None ships, so by default the scan reports "static evidence only". CyberScan does not run a similarity search over these vectors.

        Source: core/deep_embedding.py, ml/structural_classifier.py, ml/conformal.py

        Stage 06 · Implemented · online lookups off by default

        Intelligence correlation

        In plain words

        Security researchers publish lists of known harmful files and links. If you allow it, CyberScan asks three of these services at the same time whether they have seen this file's fingerprint, without sending the file itself. A match is someone else's report, not proof; no match doesn't mean safe.

        Offline, always: YARA rules (YARA-Forge via YARA-X when installed), the URLhaus malware-link list, Phishing.Database, gitleaks secret patterns and lookalike-domain checks run against local data.

        Online, opt-in: when enabled, only the file's SHA-256 (or the URL) is sent, never its contents. Three feeds are queried concurrently with asyncio: ThreatFox, URLhaus and AlienVault OTX. Fast feeds get 450 ms, and a shared deadline cancels stragglers. Every answer is normalized to one schema, and results are cached for 5 minutes.

        The indicator type is inferred first (SHA-256/SHA-1/MD5 by length, IP, URL, domain), and each feed is asked only what it supports. Overall status follows a fixed precedence: any match → matched; else all unavailable → unavailable; else any timeout → partial_timeout; else no_match.

        Contributes
        "External threat-intelligence match" (+70) when a feed reports the indicator. A match is a report, not proof, and no match is not proof of safety.

        Source: core/global_intelligence.py, core/protection.py, core/yara_engine.py, core/mitre_mapper.py

        Stage 07 · Implemented

        From evidence to explanation

        In plain words

        Every warning comes with a sentence you can check and a weight. The final score is the strongest single warning, not a pile of small ones, so many weak hints can't add up to a scary number. 0 means nothing was found (not 'safe'), 1–49 means take a look, 50 or more means be careful.

        Each finding carries a severity, a sentence a person can check, and a contribution from 0 to 100. The verdict score is the largest contribution, not the sum, so ten weak hints never add up to one strong one. A supervised model can only be blended in with an explicit weight, which defaults to zero.

        score = max( maxi contributioni, wh·heuristic + wm·model )

        Bands: 0 no indicators observed · 1–49 review · ≥ 50 suspicious. Findings are also mapped to MITRE ATT&CK techniques by keyword rules, so a reviewer can see what a behaviour is called in the shared vocabulary.

        Source: core/risk_engine.py, core/file_analyzer.py, ui/scan_service.py

        CyberScan is static analysis. It describes structure and evidence; it does not observe behaviour at run time, and a clean result is not a guarantee of safety.

          // Questions

          Questions people ask

          Is my file uploaded? Is it kept?

          On the website, your file travels over an encrypted connection to CyberScan's server, is analysed in a temporary folder and is deleted as soon as the scan ends. The website keeps no history and never shares your file. The Windows app analyses everything on your own PC.

          Is CyberScan free?

          Yes. The website, the Android app and the Windows app are free, with no account to create.

          How accurate is it?

          In our latest evaluation, CyberScan gave a strong warning on 1 of 245 clean files and repaired 84 of 86 tampered files. It is static analysis: it can miss threats that only show themselves when a program runs, so a clean result is not a guarantee.

          What can I scan?

          Programs (Windows and Linux), PDFs, Office documents, archives, scripts, emails, images with QR codes, links and pasted text. Files up to 4 MB on the website; the Windows app takes files up to 50 MB.

          Does CyberScan run my file?

          Never. Every check reads the bytes at rest: the structure, the rules, the fingerprints and the content. Nothing is opened, executed or rendered.

          Does it work offline?

          The Windows app does: its rules and known-malware fingerprints are stored on your PC, and online lookups are optional (they send only a fingerprint, never the file). The website needs a connection.

          Is there a phone or desktop app?

          Yes: a signed Android app and a Windows app with real-time folder protection, both in the "Get the app" menu at the top. Google Play, App Store and Microsoft Store listings are coming soon.

          How is it different from an antivirus?

          An antivirus stays on guard all the time and can stop programs as they run. CyberScan is the second opinion you ask before opening something: it explains what it found in plain words and can repair a clean copy.
